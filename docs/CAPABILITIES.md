# Capability matrix vs typical QML apps (0.0.10)

**Implemented** = in the code and covered by `tests/ui.rs`, unit tests or the
real-window scenario. **Partial** = usable with the stated gaps.
**Planned** = intended, not in the code. **Unsupported** = not available.
lib-fltk-omarchy does not claim QML equivalence.

Per-OS behaviour (Linux Wayland/X11, macOS, Windows) is in the last
column and in [PLATFORMS.md](PLATFORMS.md).

| Area | QML typical | lib-fltk-omarchy 0.0.10 | Status | Platforms |
|---|---|---|---|---|
| Platforms | Qt runs everywhere | one `platform` module (dirs, appearance, fonts, primary modifier, CPU time) with a fallback per OS; the rest is portable | Implemented on Linux (tested); macOS/Windows type-checked, CI jobs ready | Linux Wayland + X11, macOS, Windows |
| Omarchy look | omarchy-shell `Ui/` kit | Button, ActionButton, ButtonGroup, TextField, NumberField, TextArea, Composer, ToggleSwitch, Toggle, Slider, Hero, section header, Separator, Row, Sidebar, Dropdown, Menu, ConfirmDialog, notification cards, tooltips — same tokens as `Style.qml`/`Color.qml` plus SearchableDropdown, PopupMenu (header/context menus, clamped and scrolling, dismissal handle), TabBar, ShortcutHelp, OperationToast | Implemented: plus PopupCard, virtual Table and Tree, overflowing TabBar, localized/indeterminate OperationToast | all |
| Tooltips | Qt Quick Controls `ToolTip` (omarchy-shell `ToolTipBase`/`ToolTipSurface`, `tooltips.json`) | `tooltip`: every widget tooltip (toolkit components, plain fltk widgets, canvases that change `set_tooltip` per region) drawn in the window with the theme's `[tooltip]` colors and border, `bodySmall` font, padding, corner radius (follows `set_corners`), wrap at 360 px, centered above / flipped below, 400 ms delay and 400 ms warm hand-over; restyled on theme reloads; `~/.config/omarchy/tooltips.json` (shape, border mode/color) followed live; RTL right-aligned lines; still the accessible description | Implemented (`tests/ui.rs` hover, theme switch, black theme, corners, settings, dialog, second window, glass, RTL, canvas regions; unit tests); in-window like Qt Quick, so clipped to the window; no fade | all |
| Theme | — | colors.toml + shell.toml (theme + user override), Hyprland rounding/gaps, `monospace` font via fontconfig, live reload via inotify; strict validation on reload keeps the last valid theme (`theme::last_error`); extended colors `darker_background` / `lighter_background` / `bright_foreground` with defaults | Implemented (tested with a fake state dir and in a real window) | Linux: Omarchy files + inotify; macOS/Windows: built-in dark/light following the OS, any theme dir via `theme::set_theme_dir`, 1 s polling; fonts Menlo / Consolas |
| Window transparency | Qt `Window.color` alpha + compositor blur | `glass`: follows Omarchy Glassy windows live (toggle files), system glass opacity for surfaces, opaque text/images, Wayland opaque region cleared/restored, Hyprland does the blur; `OMARCHY_FLTK_GLASS` override | Implemented on native Wayland (buffer alpha read back in a real Hyprland window); X11/XWayland stays opaque (no ARGB visual) | Linux Wayland only; opaque on X11, macOS, Windows |
| Layouts | Row/Column/Grid/anchors | fltk-rs `Flex`/`Group`/`Grid` + `layout::{column,row,section,fit,close_fitted}` with Omarchy spacing | Implemented (anchors: use fltk positioning) | all |
| Reactive state | property bindings | `State<T>`, `map`, `combine`, `watch`/`subscribe`, bound components, two-way inputs; `state::batch` (one notification per State), in-place `modify`/`push_str` with `Edit::Appended` hints, `StateFeed`/`TextFeed` from threads ([MODELS.md](MODELS.md)) | Implemented | all |
| Data models | ListModel / QAbstractItemModel | `model::ListModel` keyed by the app's IDs: insert/remove/move/upsert/patch, `Changes` (ranges + updated IDs), `sync_from` snapshot diff, `transaction`, thread `Feed` with optional rate cap ([MODELS.md](MODELS.md)) | Implemented (randomized diff test; views redraw only changed rows) | all |
| Controls | Qt Quick Controls | the Omarchy set above plus every fltk-rs widget | Partial: no date/color pickers | all |
| Rich text / Markdown | `Text { textFormat: Text.MarkdownText }`, `TextEdit` rich text | `text::RichText`: Markdown (CommonMark + GFM tables, task lists, strikethrough, autolinks, alerts) or blocks built in code; headings, lists, quotes, code blocks with a copy button and light highlighting (diffs, comments, strings, keywords), tables, links (`on_link`, hand cursor, Tab), inline bold/italic/strike/code, theme color roles; virtualized (only blocks in view laid out), streaming (`push_markdown` re-parses the open tail only, incremental relayout), stick to bottom, `Send` sender; selection across blocks, Ctrl+A / Ctrl+C (Cmd on macOS); plain text and block ranges for accessibility. `text::RichLabel` for one line of inline Markdown | Implemented, read-only (pixel-tested; streamed == one-shot parse tested). Bidirectional lines (Unicode Bidi Algorithm, `dir=auto` per block, RTL blocks right-aligned, selection in visual order). No editing, long code lines wrap, images show as alt text | all (portable Rust + FLTK text) |
| Text editing / chat input | `TextArea` (Qt Quick Controls), a chat app's composer | `edit::TextArea`: multi-line editor with the TextField look, word wrap (CJK, graphemes), auto-grow min..max lines then scroll, placeholder, two-way `State<String>`, mouse/keyboard selection, word jumps, undo/redo with word-sized typing groups, clipboard and primary selection, context menu, input methods through `Fl::compose` + `fl_set_spot` (preedit underlined), grapheme-correct editing, atomic chips with data, incremental layout (100 KB paste ≈ 8–21 ms, ≈ 0.2–2 ms per key in release). `edit::Composer`: Enter sends / Shift+Enter new line (or Mod+Enter), send button → stop while busy, trigger completions (`@`, `$`, `/`) sync, async or from a thread in a list at the caret (active descendant for screen readers), chips for accepted items, attachment chips (`ListModel`), files from drops and `file://` pastes | Implemented (unit tests, `tests/ui.rs` with keys, pixels and AccessKit, real X11 keys in Xvfb with `script/edit-input-check`, `script/edit-bench` on Hyprland). No bidi reordering inside a line, no rich-text editing, no caret blink; a real IME preedit (fcitx5/IBus) not exercised | all (IME through FLTK: Wayland text-input v3, X11 XIM, macOS marked text, Windows IMM) |
| Virtualized lists | ListView/TableView | `List` (count + row closure, selection, keyboard, wheel, thumb) | Implemented: `List`, virtual `table::Table` (sort, resizable columns) and lazy `table::Tree`, multi-selection by ID; `from_model` variants redraw only changed rows, anchor the scroll on inserts above, keep selection by key | all |
| Keyboard / focus | focus chain, Shortcut | keyboard-first router: Tab order over the whole window, arrows only inside the focused control (`focus::scope` for groups), focus returns after menus/dialogs, every component keyboard-usable, keyboard panels (several Tab stops inside one canvas, cursor and multi-selection by stable IDs, list and grid), focus ring only in keyboard mode, `AppWindow::shortcut`, `Button::shortcut`, `focus::press` for tests ([KEYBOARD.md](KEYBOARD.md)) | Implemented (driven key by key in `tests/ui.rs`; real keys through Hyprland with `script/os-input-check`, see KEYBOARD.md); real mouse validated by hand (playground log) | all; `Mod` = Cmd on macOS, Ctrl elsewhere; labels per OS |
| Accessibility | AT-SPI (Qt Accessibility) | `a11y` on AccessKit (feature `a11y`, off by default, Rust 1.85): AT-SPI on Linux/BSD, UI Automation on Windows, NSAccessibility on macOS. Every component gets a role, a name from its visible text or tooltip, values and states. Lists, tables, trees and keyboard panels expose virtual rows with set positions; menus, dialogs and toasts appear while open; live announcements. Focus follows the keyboard router, AT actions run the keyboard code paths, plain fltk widgets get a generic node, and custom widgets implement `a11y::Accessible`. Nothing is built until an AT activates, then only changed nodes are sent ([ACCESSIBILITY.md](ACCESSIBILITY.md)) | Implemented on Linux (unit tests, `tests/ui.rs` through AccessKit's consumer, real AT-SPI read and driven by `script/a11y-check`); Windows and macOS adapters type-checked, not run | Linux AT-SPI verified (Wayland); Windows UIA and macOS NSAccessibility type-checked only |
| Menus / dialogs | Menu, Dialog | Omarchy Menu (filter, fold), ConfirmDialog, Dropdown popup; fltk-rs `dialog` and native file chooser | Implemented / Partial (file chooser not themed) | all |
| Drawing | Canvas/Shape | `gfx`: paths (Béziers, arcs, per-corner radii, squircles), anti-aliased fill/stroke with joins and caps, linear/radial/conic gradients, shadows, blur, layer opacity, blend modes, clip by shape, shape hit-testing; plus fltk-rs `draw` and `paint::*` | Implemented (pixel-tested; [SHADERS.md](SHADERS.md)) | all |
| Animations | Behavior/NumberAnimation, Transition | Omarchy control transitions (`anim`: Button 120 ms, ActionButton and rows 60 ms, Toggle 100 ms, ToggleSwitch 120 ms color + knob OutCubic, Slider 140 ms OutCubic, knob scale 110 ms); automatic layout motion for every toolkit row/column (fixed sizes, children shown/hidden/added: 190 ms OutCubic, `layout::set_visible` collapse + fade, opt-out per container); `Sidebar` hover expand (350 ms intent); popup fades (180/120 ms Omarchy easeOut); TabBar indicator slide; List (model) and Tree row motion (o3 row arrive/depart/displaced/flight); RichText message fade-in; `Anim`, `Tween`, Omarchy/o3 easings; one shared 60 fps timer, idle 0 % CPU. Follows the system setting live ([ANIMATION.md](ANIMATION.md)) | Implemented (frozen-clock pixel tests: first, middle and last frame = no-animation layout; real-window benchmark 60 fps, ≈ 1.2 ms CPU per frame). Fades are veils of the color under the widget (no layer opacity) | Linux: Hyprland `animations:enabled` (live), GNOME `enable-animations`; macOS Reduce motion; Windows animation effects (macOS/Windows type-checked) |
| Images | Image | fltk-rs images (PNG/JPEG/SVG…) | Implemented by fltk-rs | all |
| Clipboard / DnD | Clipboard, DropArea | fltk-rs `app::copy/paste`, DnD events; `edit::Composer` turns drops and `file://` pastes into paths (`on_files`, `edit::parse_files`) | Implemented by fltk-rs; file drops on the Composer | all (FLTK) |
| DPI | automatic | FLTK per-screen scaling on Wayland; spacing and fonts scale with `[font] base-size` like the shell | Implemented | Linux Wayland per-screen; others: FLTK scaling |
| Localization | qsTr | `i18n`: o3's flat JSON catalogs (toolkit catalog in 20 languages + app catalogs on top), `{name}` placeholders, CLDR plural forms as `key\|category` entries, regional → language → English fallback, system language on Linux/BSD (gettext env), macOS (CoreFoundation) and Windows (`GetUserPreferredUILanguages`), live switching through a locale `State` (`i18n::text`/`map`, `bind_text`/`bind_tooltip`/`bind_title`/`bind_placeholder`), `tr!`/`trn!`, `i18n_check` tool ([I18N.md](I18N.md)) | Implemented (unit + UI tests, Arabic/CJK snapshots); right-to-left languages mirror the layout and components live (see the next row); text input stays LTR | all (system language: env on Linux/BSD, CoreFoundation on macOS, UI-language API on Windows; macOS/Windows type-checked) |
| Right-to-left layout | `LayoutMirroring`, `Qt.RightToLeft` | `layout::Direction` from the language: rows, header, toggles, sliders, progress, tabs, lists, tables, trees, menus, dialogs and toasts mirror live on a locale switch; Left/Right follow the screen in mirrored controls, Tab goes start to end; per-container overrides `FlexExt::direction` / `layout::set_direction`; `layout::Mirror` for custom widgets ([I18N.md](I18N.md#right-to-left-languages)) | Implemented (pixel and key UI tests, `examples/rtl` snapshots in en/ar). `TextField` content stays LTR (placeholder right-aligned); RichText scrollbar stays right | all (portable) |
| Async tasks | WorkerScript | `task::Task` (bounded pool, cooperative cancel, coalesced progress, UI-thread callbacks), `task::post` | Implemented | all |
| Window modes | Window flags | `Mode::Normal` / `Mode::Floating` (float at map, header drag, corner resize via Hyprland IPC on own windows only) / `Mode::Fullscreen` (FLTK) | Implemented (native xdg_toplevel move/resize through libdecor, validated with a real mouse; Hyprland IPC as fallback) | Linux Wayland native, XWayland Hyprland IPC; X11 WMs, macOS, Windows: FLTK move/resize fallback |
| Corner preference | — | `Corners::{Omarchy, Square, Rounded}` interior radius, fixed `badge_radius` | Implemented (pixel-tested) | all |
| Headless rendering | grabToImage | `AppWindow::snapshot(path)` PNG without showing | Implemented | all (Linux needs a display connection) |
| Shader effects | ShaderEffect | CPU fragment-style shaders (`gfx::Shader`) with uniforms (time, size, pointer, theme palette), tiled, area-limited, time-budgeted | Portable shaders (`gfx::sl`): one definition, the View runs it on the GPU (feature `gpu`, off by default; monitor refresh rate) or the CPU (row interpreter, multi-core with `threads(n)`); GPU output matched the CPU evaluation in a real window. Hand-written GLSL: `gfx::gpu::GpuView` | CPU all; `gpu` builds everywhere, run-tested on Linux |
